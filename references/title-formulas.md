# 标题公式

> 来源：writing-style.md §1，qclaw-diff-report.md 对比分析

---

## 核心原则

**更短，更有冲击力，有动词或形容词。**

---

## 好/坏对照表

| 原稿风格（避免） | 发布版风格（目标） |
|---|---|
| 白话叙事感 | 短句 + 亮点词 |
| "打开一看，这虾在摸鱼" | "工作室：这虾在摸鱼？" |
| "短信一响，内测通过了" | "内测短信：龙虾入场" |
| "微信打通了，这才是重点" | "微信直控：这才是必杀技" |
| "实测第一弹：搜个马斯克" | "实测 1：追着它搜马斯克" |
| "技能商店：需要什么装什么" | "技能商店：超能力中心" |
| "4000万 token 到底够不够用？" | "4000万 Token，真的够吗？" |

---

## 规律

- **动感词优先**："必杀技"、"超能力中心"、"翻烂了"
- **反差感**："够用吗？"、"真的假的？"、"这是坑吗？"
- **数字锚点**：实测 1、第 1 步、4000万
- **疑问句**：用问号结尾，引发好奇

## 数据反馈补充

历史指标里更容易跑出来的标题，不是长技术说明，而是“第一人称 + 结果/反差”：

- `我把10个AI拉进一个群，第一天就乱了——但结果很香`
- `我花了两个小时，给自己开了一条赚美元的路`
- `我用Cursor做出了个人网站`

写 Codex / AI 工具测试文时，优先短标题：

- `我试了下 Codex`
- `Codex 有点东西`
- `手机指挥电脑`

不要写成：

- `Codex 能力测试完整复盘`
- `普通人如何借助 Codex 重塑工作流`
- `从多模态理解到本地自动化的完整案例`

---

## 官方限制

- 文章标题 ≤ **64 字**（超过 API 报 45003）
- 贴图标题 ≤ **20 字**

---

## 决策

| 场景 | 规则 |
|------|------|
| 标题太啰嗦 | 砍掉主语/连接词，只留核心信息 |
| 标题太平淡 | 加数字、反差词、问号 |
| 标题超过 64 字 | 拆成主副标题，或砍到 64 字内 |
| 标题短到看不懂 | 补回场景：谁 + 干什么 + 结果。短不是藏 |
| 关键场景是卖点时 | 宁可长几个字也要带上（2026-08-15 手改：`Grok bot给我开了个Claude账号` → `Grok bot 在它电脑上给我开了个Claude账号`，「在它电脑上」才是这事的魂） |

## 贴图标题闸（2026-08-14）

从 `SpaceZephyr/creator-buddy` 的 `baokuan-title-generator` 抽了能用的，**不整份搬进来**。每次写标题先过这闸，用户说「起标题 / 爆款标题」再按多种方法出候选。

**标题的任务**：信息流里停手指点进去。不负责概括全文，负责制造「不点会难受」的缺口——点进去必须兑现。

写之前先抽 4 个，缺的标出来，不编：

- 最有流量的实体（AI、微信、WorkBuddy…）
- 发生了什么、跟过去有何不同
- 读者能获得 / 避免 / 看懂什么
- 正文里有的数字、原话、结果；没有的不许进标题

硬规则：

- 信息密度比机械控字重要。长文中位大约 22 字；贴图硬顶 **20 字**，但不能为了短把场景砍没。
- **一遍读懂。** 读者不能问「啥意思」。藏掉「学说话 / 回微信」这种场景，再反差也是谜语。
- 先锚定一个强实体，比硬塞数字稳。一个实体够了，别堆四个品牌。
- 可以用悬念，不能用谎言。没亲测不写实测，不是刚发生不写刚刚，数字必须来自正文。
- 贴图优先：反差转折、亲测、具体场景、数字反差。不宜：时代结束、独家揭秘、空问句。

反例 / 正例（本号贴图）：

| 怪 | 为什么怪 | 改完 |
|---|---|---|
| AI写得太长，我自己才8个字 | 没说清写什么、8个字是哪 | 让AI学我说话，回微信才8个字 |
| 原来我平时回消息这么短 | 关观众啥事，跟 AI 号对不上 | 让AI学我说话，回微信才8个字 |

用户要多组标题时，至少覆盖 4 种方法，按用途给：综合首选 / 稳健 / 传播 / 搜索。不要 8 条一个套路。
