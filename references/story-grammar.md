# 成稿叙事语法（story grammar）

> 2026-08-16 从本地 29 篇发布版抽出。不是 stylometry，是「一篇怎么搭起来」。
> 朱雀「显著」的 8/15 长文，生产方法是：飞书口述 ≈ 正文，AI 只切段+配图注。
> 纯图稿要过检，先模仿这个生产方法，再谈标点和语气词。

## 先分流，再套骨架

写之前先判类型。类型错了，后面所有规则都会套歪。

| 类型 | 怎么认 | 骨架 | 代表发布版 |
|---|---|---|---|
| 长文实测 | ≥900 字，有 `## 1 2 3`，现场操作+截图 | 五拍故事 | 8/15 Grok bot 开 Claude；8/16 v5 接微信（朱雀显著） |
| 上手教程 | 一步一图，目标是读者能跟着做 | 一步一图一句 | 8/8 Reasonix 装 DeepSeek |
| 短评 / 贴图 | <600 字，一个判断就够 | 今天做了啥 + 一句判断 + hashtag | 8/15「AI 味重」；kimi 半小时做游戏 |
| 方法帖 | 教一个笨办法 | 先结论 + 步骤 + 「能落地才是好办法」 | 微信群 999+ |
| 数据复盘 | 图表+统计+「这意味着啥」 | **不要套五拍，也不要为过检加「说白了」** | 8/14 四万条：原稿较弱，语料重写掉到未发现 |
| 早期解释/时评 | 3–4 月 PART 01 结构、方法帖 | **不要当新长文 fewshot** | 库克时评 / Claude 泄露 / 10个AI进群：已发，抽干复测未发现 |

本地 29 篇里：短评 23 篇（均 280 字），长文 6 篇（均 1318 字）。
短评不要套长文的朱雀配方，也不要硬拆成 5 个小节。

## 长文五拍（8/15 发布版 = 朱雀「显著」）

这是目前唯一测过「显著」的长文结构。新长文按这个拍序填，不按「功能清单」写。

```text
HOOK     最近 + 具体动作
SETUP    这家伙是啥 + 一两句能力 + 「话不多说，开始」
拍1 装上  轻操作：下载 / 取名 / 打开
拍2 卡住  必须有事故：过不去 / 没现成方案 / 名字被占
拍3 我来  人进来：哎实在没办法了，那我来吧
拍4 意外  随口问进度，已经弄好了
拍5 再试  可选：再考验一下
CLOSE    一句判断（挺香 / 还得人看着）+ 互动句点产品名
```

发布版原句（当 few-shot，不抄事实，抄拍法）：

| 拍 | 8/15 原句 | 8/10 同类句 |
|---|---|---|
| HOOK | 最近两天，我在疯狂地用 Grok bot。 | 上回咱们把 Reasonix 装到了电脑上 |
| SETUP | 这个家伙，还是很有意思的。 / 话不多说，咱们现在开始把这个家伙用起来。 | 当时我就冒出一个念头：要是出门在外，手机上也能使唤它就好了。 |
| 卡住 | 想让它自己过，试了好几轮，根本过不去 | YOLO 权限最大，头回用建议先从一个单独的文件夹试水 |
| 我来 | 哎实在没办法了，那我来吧。 | 中途弹了个审批请求，我发现不用管它 |
| 意外 | 然后没想到，它已经弄好了！！ | 没想到还真成了 |
| 判断 | 人机验证它过不去，还是得我点一下。但随口问一句进度，账号已经开好了——这点，挺香。 | 便宜、随手、还能在手机上远程使唤，这组合我是真觉得香。 |

没有「卡住」的素材，先在图里找：验证码、报错、名字被占、现成方案没有、自己误杀进程。找不到就写「待确认：这篇缺事故」，不要用顺滑成功学补上。

## 句子来源路由（比标点更重要）

写每一句之前问：这句从哪来？

| 来源 | 怎么用 | 禁用 |
|---|---|---|
| 用户口述 / 飞书原话 | 原样织入，只切段、修错字 | 书面化重写、替他总结 |
| 截图里用户打的字（黑气泡） | 当口述用，加引号进正文 | 转述成「我让它去查微信方案」 |
| 本机语料 few-shot（`voice_fewshot.py`） | 反应短句、收口气从朋友圈/社群答疑里对齐 | 整段搬生活事实；用训练营开营稿当骨架 |
| 图里的界面文字 / 参数 | 不进正文，顶多图注一句 | 照图念 8 核、16G、选项名 |
| AI 补的连接句 | 越少越好，只负责切段和「我的反应」 | 解说腔：它查了 / 回来说 / 它解释了 |

8/15 能过检，是因为飞书口述几乎就是正文。
8/16 过不了，不是没引原话，是原话外面套了一层解说：「还真去查了。回来说现成的连接器里压根没有微信」。

对照：

```text
❌ 解说腔（AI 织稿）
还真去查了。回来说现成的连接器里压根没有微信

✅ 原话 + 反应（发布版拍法）
「我现在人在中国大陆，我想通过微信 clawbot 远程控制你」
现成的里面没有微信。就这？我不死心
```

禁止默认解说腔（写完全文搜一遍，命中就改）：

- 它查了 / 它解释了 / 回来说 / 它翻出 / 它建了
- 它马上切中文，用人话挨个讲明白了
- 查完跟我说

改成：用户原话 → 图 → 我的短反应（就这？ / 行 / 好嘛那验证啰 / 666 啊）。

## 纯图成稿：按「口述缝合」来做（2026-08-16 v5 复测：显著）

没有飞书口述时，不要「看图写一篇解说」。按 8/15 的生产方法做等价物：

1. **先出原话表，再动笔**  
   逐张图列出：用户气泡原文、bot 关键回复（只留结论，不翻译成长段）、这张图是五拍里的哪一拍。  
   原话表写进草稿 `manifest.md`。表是空的，稿就是空的。

2. **选一篇同类型发布版当骨架**  
   长文实测默认套 8/15；教程套 8/8；连载下一篇套 8/10。  
   学的是：段数节奏、拍序、引号出现的位置。不搬句子，不搬选题。

3. **用原话填骨架**  
   每一拍 = 用户原话（或截图气泡）+ 图 + 一句反应。  
   AI 只写反应短句，不写「它做了什么」的旁白。  
   图注描述腔，不写金句。

4. **套手改操作（确定性，最后一公里）**  
   段尾默认无句号，约 1/5 自然收口带；图注一律无句号；小节标题砍第二分句、可带情绪；句尾补气口（嗐 / 啊 / 哈）；长段拆行；互动句点产品名。

5. **QC + 可选朱雀**  
   stylometry 全过是底线，不是过检保证。  
   交付时写清：本篇原话来源是口述 / 截图气泡 / 几乎没有。  
   几乎没有原话的，标注「建议发布前快速手改一遍」。

8/16 v5 按上面 1–4 步写完，本机朱雀 =「显著」（对照：同题材 AI 织稿各版 =「较弱」）。单次结果，下一篇复测。

想更稳：60 秒口述（语音转写 200 字也行）按时间线把五拍讲完。口述 + 气泡叠在一起，起点更高。

## 短评骨架（23/29 篇是这个，别写成小论文）

```text
今天 / 前两天 + 做了啥
一两句判断（太香了呀 / 相当得劲了哈哈 / 能落地的才是好办法）
不分析、不升华
能加 hashtag 就加
```

用户自己的贴图发布版就是这样。不要用长文五拍去扩写短评。

## 交付前自检（长文）

- [ ] 类型判对了
- [ ] 五拍齐：尤其「卡住」和「意外」有素材或已标待确认
- [ ] 正文骨架是原话/气泡，不是解说旁白
- [ ] 全文搜过禁止解说腔，无命中
- [ ] 没照图念参数
- [ ] 图注是描述不是金句
- [ ] 手改操作套过
- [ ] QC stylometry hits 为空
- [ ] `voice_match.py` 不是 UNLIKE，hits 为空
- [ ] 朱雀显著或较强；为过检改口气则两道重测
