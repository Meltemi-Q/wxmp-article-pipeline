# 个人口吻规则

> 来源：Obsidian user 语料抽样与历史写作复盘。只提炼表达方式，不把隐私事实写入文章。

## 核心判断

用户的表达底层不是“标准公众号腔”，而是“现场校准”。

常见句式：

- `这个地方的话...`
- `应该说...`
- `我大概的想法是...`
- `可能...`
- `你看看是不是...`
- `还是不要...`
- `不是 A，而是 B`

写稿时可以保留这种“边判断边修正”的味道，但要比原始语音更短、更顺。

## 要保留

- 先给判断，再补原因。
- 允许自我修正，比如：`准确说，不是让它替我发文章，是让它先把素材整理好。`
- 多用工作现场词：`先存下来`、`后面好找`、`跑一遍`、`截图留证据`、`能不能复用`。
- 多用轻判断：`有点意思`、`不太对`、`这个点挺小，但有用`、`还得人看着`。
- 讲工具时落到可见动作：`手机发一张图`、`电脑里多了一个文件夹`、`表格里挑出三件事`。

## 要压掉

- 不要每段都收成口号。
- 不要连续排比抽象名词。
- 不要写 `本文将从...展开`。
- 不要写 `在这个 AI 时代`。
- 不要把工具能力吹成革命。
- 不要把个人实验写成通用成功学。

## 最新纠偏：别用“模型收束句”

这些表达容易被用户判定为 AI/GPT 味：

| 不要写 | 为什么 | 可替换方向 |
|---|---|---|
| `可以这样收` | 像模型在交作业，不像正文 | 直接进入最后一段感受 |
| `现在还不敢说它能替我干完所有事` | 标准免责声明，太顺滑 | `标题、选图、哪些能发，还是得人看。` |
| `把电脑里的事接起来` | 抽象，不像人话 | `手机上发一句，电脑上那边的 Codex 接着把文件、图片、记录处理完。` |
| `把这条链路打通` | 技术汇报腔 | `这几步它能先干起来。` |

写 Codex / Agent 体验文时，优先用“动作 + 文件/截图结果”：

- `手机上发一句。`
- `电脑里多了一个素材文件夹。`
- `它把图片识别、文字摘出来、规则改好。`
- `最后哪些能发，还是我来判断。`

## 可复用句式

- `我一开始以为它只是回我一段话。后来发现，它能真去电脑里做事。`
- `这个点很小，但很要命：素材先得找得到。`
- `我不想把它写成教程。教程容易变味，也容易让人误解。`
- `我更想试的是：一个普通老板、小白，能不能看懂它到底省了哪一步。`
- `神不神先放一边，截图能不能留下来，文件能不能找到，这个更实在。`
- `我现在对 AI 的要求越来越简单：别只会说，先帮我把第一版做出来。`

## 使用纪律

- 有 Obsidian / 历史聊天语料可读时，写稿前先提炼本篇相关口吻。
- 不要直接搬隐私事实、人名、金额、账号、客户信息。
- 不要为了“像真人”故意写错别字。
- 如果用户现场修正了方向，优先保留修正痕迹，而不是继续套旧模板。

## 最新纠偏 v2（2026-05-19，来自 GPT 岗位文改稿）

用户当场把几处“很 AI”的写法改了，把规律固化下来，下次举一反三：

### 小节标题用口语疑问句 / 带情绪，不用平铺直叙

| 平铺直叙（偏 AI） | 用户改法（采用） |
|---|---|
| `参考图转风格` | `插画师的它，做了些啥？` |
| `文章生成学习图` | `内容编辑做出来的图有点哇塞` |
| `改 Word 试卷` | `出卷子的老师又双叒叕省心啦` |
| `我现在的感觉` | `它能搞定这些事情，那又怎？` |

小节标题可以是疑问句、可以带梗、可以带情绪，只要还是 `## 数字 标题` 结构即可。

### 别用“交作业式”的结构说明句

- ❌ `我就按“我让它干了什么”来讲：一件事，对一个岗位。`（像在交大纲）
- ✅ `干这些事儿它都贼啦利索，我来带你看看它帮我干了啥。`（像在跟人唠）

### 允许网络口语和梗

`（狗头）`、`又双叒叕`、`有点哇塞`、`贼啦利索`、`那又怎` 这类都能用，是用户真实语感，别为了“规范”抹平成书面语。

### 评价要带个人态度，好坏都说

- 用户原话样例：`有好的该夸夸，不咋地的点也得拉出来鞭一鞭（狗头）`
- 夸归夸，缺点也直接点，比如 `毕竟目前没啥模型能全知全能`。

### 用户会自己口述段落原话 → 优先照搬

用户经常直接给一整段口语原话（如拆解小狗那段复盘）。这种**优先照搬**，只做顺序调整、错字修复、段落切分，不要书面化重写。这是“留住用户味儿”的关键。

## 最新纠偏 v3（2026-08-15，贴图发布手改 + 微信语料）

### 四套味道别混（2026-08-17 全量语料，取代「三套」）

本机实测，不是印象：

| | 私聊 | 社群答疑 | 朋友圈 | 公众号成稿 |
|---|---|---|---|---|
| 规模 | 26809 条 | 答疑约 1100 条（陪伴群+变现营） | 830 条有正文 / 12.6 万字 | 本地约 50 篇 |
| 中位长度 | 8 字 | 答疑 15–40 字；开营稿会突然变长 | 72 字 | 一段一两句 |
| 口头禅 | 哈哈 / 好像 / ok / 吧 / 呀 | 说白了 / 手机上也可以 / 欢迎 / 666 | ～ / 哈哈哈 / 持续 / ➕ / 安排 / 搞定 | 咱们 / 这家伙 / 成了 / 没想到 |
| 结构 | 没有结构 | 先一句人话，再补怎么做 | 画面 + 一句感受 + 表情收尾 | `## 1 口语小标题`，五拍 |
| 金句 | 很少 | 偶尔「说白了就是…」 | 很少，靠画面 | 一篇最多一两处 blockquote |

写公众号时：

- **反应短句**去捞朋友圈 2024-2026、社群答疑，不要用私聊 8 字碎片直接当正文。
- **不要用训练营开营稿**（首先自我介绍、①②③④⑤闭环）。那是另一套，朱雀会判成教程复盘腔。
- 朋友圈标点是他的：`～`、`➕`、段尾表情。正文可借口气，别整段搬生活事实。

飞书/口述稿是第二套。**优先照搬原话**，只做切段和配图，不要改成第三套的分析文。

### 发布前手改：通常更短，少分析

2026-08-15《AI总是写内容不像你或 AI 味重？原因在这！》发布版 vs 推送前草稿：

| 草稿容易写成 | 用户手改后 |
|---|---|
| 长段分析、私聊群聊对照、升华 | 短句 + ①②③④ 清单 |
| 「4万条」这种模型口径 | 改成他自己的说法，比如「4万多字」 |
| 先讲方法再讲感受 | 先甩自己看到的几条，再一句「就是因为它不懂你」 |
| 贴图也写成小论文 | 贴图就短，能加 hashtag 就加 |

写长文时也要吃这口药：少写「这意味着啥」，多留「话不多说，咱们现在开始」「好嘛那验证啰」「然后没想到，他已经弄好了」。

### 标题别替他吹过头

用户飞书里会随手写「全自动」「几分钟」。正文如果已经写了「人机验证我自己点的」，标题就不要再写全自动。数字、时间以正文证据为准，不要为了标题党补上去。

## 最新纠偏 v4（2026-08-15，Grok bot 篇发布手改 diff 实测）

来源：`scripts/compare_publish_edits.py` 对「推送版 vs 发布版」逐段 diff。这次用户手改 19 处纯标点 + 11 处语气用词，规律如下，写稿时直接按发布版口径写：

### 标点：段尾句号少用但别删光（2026-08-16 修正）

用户语料档案本来就写着「少堆句号」。8/15 发布版把段尾句号删了 19 处、图注句号 16/16 全删，但**没有删光**——「这个家伙，还是很有意思的。」「话不多说，咱们现在开始把这个家伙用起来。」这类自然收口句保留了句号。

- 默认：段尾不写「。」，图注一律不写
- 但每篇留少量（大约五分之一）自然收口句带句号，**混合节奏才像人**；机械全删反而是 AI 特征（朱雀检测实测教训）
- 段落**中间**的句号照写；`？` `！` 保留
- QC 的 `paragraph_trailing_period_hits` 少量命中（<8 处）可接受，`caption_trailing_period_hits` 仍要求为空

### 语气词：句尾补气口，别写成书面句

| 推送版 | 用户改后 |
|---|---|
| `还是不行。` | `还是不行，嗐` |
| `就很像个真的员工在搞啊，666。` | `就很像个真的员工在搞啊，666 啊` |
| `它自己搞定。` | `它自己能搞定` |
| `还是得我配合一下。` | `还是得我来配合` |
| `这关得我来点。` | `这关得我来` |

### 小节标题：更短、可感叹，砍第二分句

- `2 人机验证它过不去，这波我来` → `2 人机验证它居然过不去！`
- `4 随口问进度，Claude账号已经开好了` → `4 Claude账号直接给我开好`

### 主标题：关键场景不能省

- `Grok bot给我开了个Claude账号` → `Grok bot 在它电脑上给我开了个Claude账号`——「在它电脑上」是这事的魂，标题宁可长几个字也要带上

### 其他

- 长段一句一段拆行：`手机上目前只支持苹果 iOS…都能装。` 和 `聊过的内容还会同步…` 拆成两段
- 结尾互动句点产品名不用代词：`你最想让它帮你干点啥？` → `你最想让 Grok bot 帮你干点啥？`
- 用词就低不就玄：`画图` → `生成图片`，`文件` → `文件管理器`
- 每次发布后跑 `python3 scripts/compare_publish_edits.py --archive-dir <存档目录>`，新规律持续补进本节

## 图片内容别复述太细（2026-08-16 用户反馈）

用户原话：「我好像不会对图片内容描述的那么详细吧」。

- 正文不照图念参数、念选项、念界面元素——读者自己会看图。❌ `8 核 Xeon、16G 内存、约 126G 磁盘，Cursor Ultra 约 200 美元…` → ✅ `配置、价格它列得清清楚楚，具体的数都在图里`
- 图里的小彩蛋（时间戳、搜索框文字）放**图注**一句带过，不进正文铺陈
- 用户自己的写法参照：`看看它截图过来的界面，完全 ok 哈`——一句话+让读者看图

## 图注写「描述」不写「总结金句」（2026-08-16 朱雀检测教训）

- ❌ 总结对仗腔：`不糊弄，手动是手动，自动是自动`、`两边都对上了，信是真的能走`——每张图下面来一句小金句，是典型 AI 特征
- ✅ 描述腔：`它出的登录码，用微信里的 ClawBot 扫`、`15:25 发的你好，15:26 它回的`——说图里是什么就行
- 用户发布版图注全是描述腔：`打开就是 Sign in，有套餐就能直接登`

## 朱雀 AI 检测实测结论（2026-08-16，matrix.tencent.com/ai-detect）

同题材四个文本实测：**用户手改后的发布版=「人工创作特征显著」；AI 各版（含两轮针对性去 AI 化：标点混合、砍修辞、图注描述腔）=「人工创作特征较弱」**。

- 说明：表层改写（标点/句式/修辞）骗不过统计特征；用户随手改 30 处就能从「较弱」翻到「显著」
- 实操：**发布前用户快速手改一遍，就是最好的过检方式**，不要指望 AI 自己改到「显著」
- 用法：把正文纯文本贴 https://matrix.tencent.com/ai-detect/ ，免登录每天 5 次；结果仅参考，不作为发布门槛

### 可复用的口气（来自语料，不是模型编的）

| 场景 | 口气 | 不要写成 |
